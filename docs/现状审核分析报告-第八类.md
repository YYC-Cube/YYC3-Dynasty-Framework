## 一、项目现状概述

### 1.1 项目定位

YYC3-Dynasty-Framework 是一个**事件驱动的 AI Agent 协作平台**，以"三省六部"中国古代官制为隐喻，构建多 Agent 任务协作系统。项目由三部分组成：

| 子系统 | 技术栈 | 功能 |
|--------|--------|------|
| **edict/backend** | Python FastAPI + PostgreSQL + Redis Streams | 任务 API、事件总线、状态机、多频道通知 |
| **edict/frontend** | React 18 + TypeScript + Zustand + Vite | 三省六部总控台 Dashboard |
| **scripts/ + dashboard/** | Python | 数据同步、看板操作、简单 Web 面板 |
| **agents/** | Markdown SOUL 文件 | 各 Agent 灵魂设定，定义角色/职责/个性 |

### ⚠️ 2.2 类型定义完整性

**关键发现：前端 `api.ts`类型定义存在不一致**

| 问题 | 文件 | 严重度 |
|------|------|--------|
| `CreateTaskPayload` 中 `targetDept` 使用 camelCase，后端 Python 模型用 `target_dept` snake_case | `api.ts:401`, `task.py:97` | ⚠️ 中 |
| `MorningBrief.categories` 类型为 `Record<string, MorningNewsItem[]>`，但实际数据结构中 items 含 `_kwHits` 运行时字段 | `api.ts:262` | ⚠️ 低 |
| `FlowEntry.remark` | 前端用 `remark`，但 EventBus 发布事件时用 `reason` | ⚠️ 中 |

**改进建议：** 在前后端之间建立统一的 API schema 规范，使用 `pydantic` 自动生成 OpenAPI 规范，前端通过 `openapi-typescript` 生成类型。

### ✅ 2.3 错误处理完善性

| 层级 | 状态 | 说明 |
|------|------|------|
| 前端 API 调用 | ✅ 统一 | 全部使用 `try/catch` + `toast()` 模式 |
| 后端异常 | ✅ 规范 | 使用 `HTTPException` + `ValueError` 分层异常 |
| 网络错误 | ✅ | 所有 API 调用有 `catch { toast(msg, 'err') }` |
| 空数据处理 | ✅ | `||` 和 `?.` 链式调用处理 |

**发现的问题：**

1. **后端 `live_status` 未处理空 tasks** — 当 DB 无任务时返回 `{"tasks": {}, "completed_tasks": {}}`，前端期望 `tasks` 为数组类型 `Task[]`
2. **`silently fail` 模式过多** — store.ts 中 8 处 `.catch(() => {})`，静默吞掉错误，调试困难

```typescript
// store.ts - 典型静默失败
loadMorning: async () => {
    try {
      const [brief, config] = await Promise.all([api.morningBrief(), api.morningConfig()]);
      set({ morningBrief: brief, subConfig: config });
    } catch {
      // silently fail ← 错误被吞掉，用户无感知
    }
  },
```

### ⚠️ 2.4 性能优化程度

| 优化项 | 状态 | 说明 |
|--------|------|------|
| 列表渲染 key | ✅ | 全部使用唯一 ID |
| 按需加载 | ⚠️ | 所有组件一次加载，未用 `React.lazy`/`Suspense` |
| 内存泄漏防范 | ⚠️ | `useEffect` 清理函数缺失或遗漏 |
| 轮询频率 | ✅ | 合理（5s 倒计时） |
| 后端查询性能 | ✅ | 使用索引 + `SELECT FOR UPDATE` 防并发 |
| 后端连接池 | ✅ | `pool_size=10, max_overflow=20` |

**发现的问题：**

1. **`useEffect` 清理不完整** — `MonitorPanel.tsx:13` 调用 `loadAgentsStatus()` 但组件卸载时无清理
2. **无路由懒加载** — `App.tsx` 同时 import 13 个组件，首屏 JS 包约 271KB
3. **前端 bundle 体积** — Vite 构建产物 271KB JS + 58KB CSS，对 MVP 尚可，建议后续做 code splitting
